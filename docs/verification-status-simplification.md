## 自动化与反向验证

入口：`npm run check`；单独测试为 `npm test`。SDK 场景使用真实 Pi 生命周期与工具包装层，模型回复由本地 fixture 提供。

新增 `test/recording-only.test.ts`，并调整原有录制、恢复和终止工具测试：四种旧非活动状态得到相同的无状态阅读输出与摘要输入，读取不归一化历史行；保留原文中的状态词。缺少或不匹配的工具结果照实保存，`agent_settled` 仅结束录制，不再推断成功、失败或待确认。消息和工具事件中的错误、终止信息仍保留。

本轮完整检查中实际被拒绝的输入：

| 输入 | 结果 |
| --- | --- |
| 正在录制时 `/runs summary r1`；删除活动 Run | 不发摘要请求，不删除记录；停止录制后可正常摘要 |
| 删除批次混入未知/活动 Run、空批次或空原因；错误类型参数 | 整批拒绝，Pi 参数校验先于副作用 |
| 删除中途由 SQLite 触发器报错 | 消息、Run 和墓碑全部回滚 |
| 绕过约束写入未知录制编码 | 读取和删除明确报错，消息不丢失 |
| 坏 JSON、null、缺少 role 的消息 | 文本读取明确报错，raw 仍可读存储字节 |
| 外来/旧版库、存活写入者冲突、伪造游标、非法时间与页大小 | 拒绝打开、接管或查询 |
| 空白、超长、未结束、试图调用工具的摘要 | 不保存、不执行工具；重试有界 |

真实子进程 SIGKILL 后，在原会话和另一会话分别恢复：已提交消息保留、录制标记释放，未知结束时间保持 `null`；页面不添加“结束待确认”。分页、检索排除范围、终端控制序列、取消及资源释放也重跑通过。

### 真实模型与摘要

实际入口（本机已有 OAuth 认证，无凭据复制）：

```bash
PI_PROVIDER=openai-codex PI_MODEL=gpt-6-astra EVIDENCE_DIR=/tmp/pi-runs-no-status-DYs4rB/live node test/live-check.ts
```

脚本要求新的证据目录，复跑请更换 `EVIDENCE_DIR`。主请求上限 1 次／45 秒，摘要上限 2 次／总超时 120 秒；实际为 1 次主请求、1 次摘要。

直接审阅完整请求、响应及查询结果：主请求只有本次用户消息和三个归档工具，没有历史注入；摘要输入没有 Run 状态字段。回复为“已收到验证请求；未修改文件。”，摘要依据该回复说明进展，阅读标题只含编号和时间。原始模型消息中的 `rawStopReason` 等字段未删改。

此次联网场景没有执行工具；三个工具的实际执行由 SDK fixture 验证。当次全部 `src/*.ts` 的运行前后哈希一致，收口时与该次交付源码核对；此后的工具阅读与调用卡片改动未沿用这次联网结论。
