## 结果与边界

`find_run`、`get_message_detail`、`delete_run` 已通过已安装工具实际执行。随后修复无正文模型错误的预览／搜索，以及对话调用卡片没有参数、默认结果冗长的问题。`npm run check` 最终通过 39 项测试、类型检查、构建和 Biome；本轮没有新增外部模型请求。

Shadow 来源混杂仍未修复：`r38` 的用户输入以 `<main-agent-trajectory>` 开头，含旧主任务上下文，摘要把其中的早期待办沿用为当时进展；`r36` 与 `r38` 的 `agent_id` 同为 `pi`，`title` 均为空。现有标签不足以可靠区分，不能凭旧摘要判断当前任务，也不凭文本标记擅自过滤历史。

## 三个工具的实际使用

- 查找：按目录列举、分页续查、正文关键词搜索和按 Run ID 阅读；消息详情读取真实用户消息、工具结果与模型错误的 text/raw。
- 删除：只针对本次创建并明确标记的三个合成 Run。`r41/r42` 批量删除成功，重复调用返回 `alreadyDeleted`；`r43` 在停止临时录制器后删除。事后核对三个样本的 Run、消息、事件均移除，临时 writer 已释放，目录查询为空；仅保留正常墓碑及归属元数据。
- 拒绝：批次混入活动 Run 或未知 ID 时整批拒绝，核对三个样本及已有墓碑没有变化；坏游标被拒绝，删除后的消息详情明确不可读。

实际工具调用发生在修复前的已加载实例。修复后使用新建的隔离 SDK 会话执行工具，不把前面的成功调用当作新代码复验。

## 发现与修复

### 错误内容可读、可搜

真实 `m1412` 的正文为空，错误信息位于 `stopReason: "error"` 与 `errorMessage: "fetch failed"`；原预览为空，按错误文本搜不到。

当前预览优先显示可读错误；搜索把 assistant 的 `errorMessage` 作为独立文本块，仍排除思考、传输诊断、工具参数和其他元数据。未改变存储、详情正文，也未恢复 Run 状态分类。新建隔离 SDK 会话重放这份真实错误，直接查看错误预览，并将 raw 解析结果与原件逐字段对账。

### 对话工具卡片

三个调用标题显示参数。`find_run` 默认给本页数量、最多三个候选和续页提示，展开显示完整结果；模型结果正文保持不变。UI 导航快照只保留少量标签，避免重复保存全文或重新查询已经变化的归档。

在实际 Pi 窗口回放 SDK 产生的同一份合成工具会话，比较旧／新源码：新卡片可直接看到 query、scope、cwd、limit，默认结果不再被时间、路径和继续调用 JSON 淹没。走通 `Ctrl+O` 展开／收起、`/reload`，并查看 100 列常规界面、100×60 展开界面和 40×22 窄屏。

第一次实际回放发现已完成的旧卡片仍显示“参数接收中”：宿主恢复结果时没有重放 `argsComplete`。已按最终结果修正展示条件，补上恢复回归，并再次实际重载检查。最终退出后，隔离库的 writer 数量为零。这里审阅的是实际终端渲染帧，不是网页截图。

## 自动化反向覆盖

新增 `test/error-reading.test.ts` 与 `test/tool-render.test.ts`，其余 32 项状态简化及既有回归一起重跑。

| 输入或状态 | 实际结果 |
| --- | --- |
| 只在思考、工具参数、传输诊断或其他元数据中出现关键词；跨正文／错误块拼接关键词 | 不命中 |
| 错误前有很长正文 | 错误仍出现在预览开头；raw 不变 |
| UI 导航元数据为空、损坏、负数计数或计数与候选矛盾 | 退回有限行数的原文，不把它当成有效候选页 |
| OSC 剪贴板序列、C1 控制符、长路径及中文／emoji | 控制符保持惰性；12、24、40、100 列的原生工具组件没有超宽行 |
| 本页零命中但仍有续页 | 明示还有未搜索历史，不声称全库没有 |
| 参数未收齐、执行中、失败、恢复的已完成调用 | 对应展示；最终结果不会残留接收／执行提示 |

组件测试还检查浅色／深色主题重绘及三个工具的参数；SDK 测试逐字比较 `find_run` 的工具正文，确认增加导航快照没有截短模型结果。完整多插件 UI、真实模型流式参数的终端演示未新增验收。
