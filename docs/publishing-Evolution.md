# npm 发布 Evolution

## 2026-09-17 · 建立发布入口与包级验证

- 发生：三个本地 Pi 插件需要发布到 npm；最初假定 `npm pack --json` 始终返回数组，本机 npm 12.0.2 实测返回以包名为键的对象，导致包验证脚本失败。
- 分析：本地和 GitHub Actions 的 npm 版本可能不同；源码检查通过不能证明 tarball 可安装、可加载或包含查看器资源。
- 改变：建立 tag → 检查 → tarball 隔离安装 → OIDC 发布流程；包解析通过 `Object.values` 同时处理两种输出格式，维护说明要求升级 npm 后执行真实包验证。首次发布保留显式人工认证，不保存长期发布 token。

## 2026-09-17 · 修正干净环境类型检查

- 发生：Actions 干净安装后，Pi 的传递依赖 `@google/genai` 声明引用未安装的可选 MCP SDK，类型检查失败；本机已有依赖掩盖了问题。
- 分析：本项目不使用该可选能力；额外安装整套 SDK 只为检查第三方声明，会增加不必要的开发依赖。
- 改变：与 pi-notes 一致启用 `skipLibCheck`，跳过第三方声明检查；项目源码严格检查、测试和 tarball 隔离加载保持生效。
