## 用户命令

| 命令 | 行为 |
| --- | --- |
| `/runs` | 当前目录的近期历史 |
| `/runs search <关键词>` | 当前目录内搜索摘要与正文 |
| `/runs all` | 全库近期历史 |
| `/runs r1` | 某个 Run 的消息预览 |
| `/runs r1/m2`、`/runs r1/m2 raw` | 消息文本或原始 JSON |
| `/runs summary r1` | 后台补生成缺失摘要；已有摘要保持不变 |
| `/runs debug` | 当前库路径、录制错误、摘要开关和最近摘要错误 |

ID 是示例，请使用实际返回的 ID。阅读界面支持 `O` 打开、`N` 续页、`S` 搜索、`A` 扩大到全库、`F` 切换文本/JSON、`R` 刷新；Esc 返回上一层，方向键和 Page Up/Down 滚动。以各页底部提示为准。TUI 提供完整阅读界面，RPC 以通知展示查询结果；print/JSON 模式通过模型工具读取归档。

## 模型工具

对话中的三个工具卡片显示调用参数。`find_run` 默认显示本页数量、最多三个候选及是否还有后续页；使用 Pi 的工具展开快捷键（默认 `Ctrl+O`）查看本页完整结果和被截短的参数，再按一次收起。展开不会发起新的查询，模型收到的结果正文保持完整。已有会话缺少导航快照时，卡片使用有限行数的原文预览。

### find_run：先定位，再读预览

```json
{"query":"数据库 索引","scope":"all","limit":20}
```

- `query`：字面关键词，以空白分词；ASCII 英文大小写不敏感。正文命中要求全部词出现在同一文本块，不做语义检索。包含 assistant 的可读 `errorMessage`，将它作为独立文本块；不搜索附件编码、思考、工具参数、传输诊断或其他元数据。
- `scope`：`all`（默认）、`summary` 或 `content`。摘要范围也包含首条用户目标摘录、工作目录与内部 agent 标识；`content` 要求非空关键词。
- `cwd`：精确匹配绝对目录，省略为全库；不是目录前缀匹配。
- `since` / `until`：按 Run 开始时间筛选，前者包含、后者不包含，使用带时区的 ISO 时间。
- `limit`：1–50，默认 20。省略关键词可列举近期历史；列举/搜索不包含活动 Run。
- `id`：按 `r1` 或完整 Run UUID 定位，返回时间顺序的消息预览。此时只可同时传 `limit` / `cursor`，可读取活动 Run 已落库的消息。

搜索是分段扫描，**本页未命中不等于全库没有**。只要返回继续调用就仍有历史可读；按原样续用 `cursor`。改变筛选、重新加载扩展或重启后，重新发起查询。

### get_message_detail：完整下钻

```json
{"id":"r5/m3","format":"raw"}
```

`id` 支持返回的 Run 内复合编号（`r5/m3`，消息号随 Run 重新计数）或完整 Message UUID；旧版本归档输出中的库级 `m` 编号也继续可用。默认 `text` 展示正文、思考、工具参数及结果；`raw` 返回原始保存的消息 JSON，包含附件编码等字段。

正文每页最多 12,000 字节。顺序拼接各页分隔线之间的正文即可还原，续页参数见返回结果。文本投影超过 8 MiB 时需改用 `raw`；原始数据不会因此截断。TUI 会移除终端控制序列以保护显示，工具返回的原始 JSON 仍保持归档内容。

### delete_run：用户授权的清理

参数为 `ids`（1–200 个 Run ID）和非空 `reason`（最多 500 字符）。代码先校验整批，再在一个事务内删除；活动或不存在的 Run、任意删除失败都使整批回滚。重复删除已删除的 ID 返回 `alreadyDeleted`。

自然语言授权是工具使用约定，不是程序验证出的权限凭据。AI 只能在用户明确要求或授权的范围内清理，可在该范围内自行选择一批记录，无须逐条确认。

删除移除指定 Run、其消息、事件和摘要，保留 ID、删除时间和原因。它是归档层的逻辑删除，不是磁盘安全擦除；不会缩小 SQLite 文件，也不会删除 Pi 会话中的副本、备份或其他 Run 引用过的文本。

## 录制、摘要与退出

Run 从 `agent_start` 开始录制，到 `agent_settled` 停止录制；自动重试、steering 和已排队的 follow-up 留在同一 Run。插件按宿主事件保存记录，发生了什么由摘要和消息原文说明。内部录制中标记保护追加写入、删除和摘要时机，对外不展示状态分类。

完整消息在 `message_end` 落库；流式中间帧不逐帧写入。进程崩溃时保留已提交消息，未结束的流式内容不保证保存。同机重新挂接任意会话会识别已死亡的写入者并释放录制标记，已有记录随即可查；结束时间只保存实际观察值，不读取 Pi JSONL 补写历史。录制错误会提示并请求停止执行，修复后需重新加载。

已有 v2 归档可直接继续使用，旧摘要与原文保持原样，包括其中描述失败、中止或“已收束”的文字。

摘要与主对话分开调用：使用结束时选中的模型，最多 200 个 Unicode 字符，仅阅读本轮目标摘录和有省略标记的有限消息证据，不执行工具。每项最多尝试两次，共享 120 秒超时；队列最多八项，超出会记录失败，原文仍保留。摘要会把这部分归档证据发给对应模型服务。

TUI/RPC 退出、重载或切换会话时取消未完成摘要；正常 print/JSON 退出最多等待 30 秒。取消或崩溃留下的缺失摘要可显式重试，当前没有启动时批量补摘要或自主清理。

## 与其他 Agent/插件协作

v2 只观察加载了它的 Pi 会话事件，按 Pi session ID 隔离录制。工具是否出现在模型可用清单中，与扩展是否加载并录制是两件事。后台摘要本身不创建 AgentSession，不会把摘要再录成一个 Run。

Shadow 等子 Agent 若加载 v2 并正常驱动会话事件，同样可能产生独立 Run。已在自然积累的记录中观察到包含 Shadow 主轨迹输入的 Run，但仍没有专用 Shadow 来源标识或过滤开关，摘要也可能把旧输入误当成当前进展。尚未完整验收真实 Shadow 的录制与摘要链路；不能把通用“终止工具/取消”测试视为这项验收。SDK 集成方应正确驱动启动与 `session_shutdown`，释放录制器和摘要资源。
