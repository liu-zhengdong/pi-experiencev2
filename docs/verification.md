## 2026-09-22 · find_run 描述改写的真实调用验证

`npm run check` 通过类型检查、56 项测试、构建与 Biome。构建后加载 dist 打印 `find_run` 的实际描述与参数 JSON Schema，按模型收到的样子逐字核对：顶层描述 76 → 104 词，字段说明 24 → 171 词，工具全部说明文字 100 → 275 词。

真实调用对照 18 次（claude-bridge / claude-opus-5，thinking off，隔离归档库，只加载 claude-bridge 与本扩展，关闭上下文文件、技能与提示模板）。两臂分别指向改前 `src/index.ts` 与本分支源码，其余参数相同：

- 空会话单轮提问「我记得你之前说过 Slidev 那个方案不行」，两臂各 3 次；另一组同时加载提供 `search_context` 的上下文扩展、问「我们之前讨论过的那个决定」，两臂各 3 次。
- 从同一条预置会话 fork 出带上下文的单轮提问，两臂各 3 次；上下文里刚讨论过 Slidev，模型有可以直接作答的材料。

**触发率没有测出差异：** 18/18 两臂的第一个动作都是 `find_run`，没有出现无效参数，`search_context` 那 6 次两臂都没有改用它。用户报告的「想不到用」在这些裸会话条件下没能复现——空会话里模型本来无事可做，触发率已经是满的。改写的依据是描述里确实没有任何说明何时该查的内容，此处只验证了没有回退。

**唯一测到的差异在首页未命中之后：** 带上下文那组，新描述 3/3 会换一组关键词再查一次，旧描述 3/3 停在一次查询就转为凭当前上下文作答。

测量本身做了反向确认：同一条件下用 `-xt find_run` 屏蔽工具复跑一次，记录为无调用，确认观察面能显示零调用，18/18 不是解析漏读。

**尚未验证：** 真实长上下文、完整工具集与 AGENTS.md／技能同时在场时的触发率，以及非 Claude 模型。原始 JSONL 证据留在库外临时目录，未随仓库提交。

## 2026-09-19 · 查询 OR 与短语

`query` 增加大写 `OR` 与双引号短语，空白 AND 与同一文本块命中不变。覆盖解析、摘要 SQL、正文扫描，以及未闭合引号、空 OR 子句、小写 `or` 仍当字面词、短语不连续则不命中。`npm run check` 53 项测试通过。本轮没有新开 Pi 窗口或真实模型调用。
